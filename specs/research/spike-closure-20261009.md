The six-page, panelized/escalating LTR scope is now executed and recorded in the [four-format report](actual-four-format-prefix6-v30-validation-20261009.md). The protocol below is preserved for reproducibility, not an instruction to repeat paid calls or rerun unchanged tests. Broader direction/device/size claims retain their separate scope.

Run all executable steps in disposable VM153. Use the exact frozen candidate, fresh evidence/output directories and the genuine portable RAR5 archiver already retained in its task directory. Keep stable Build10, source files and the shared ledger unchanged. This protocol reuses **provider responses**, never manually selected final geometry or a curated result catalog.

1. **Freeze identity.** Record candidate source/prompt/schema hashes, CLI flags, original PDF SHA, verified render-cache manifest, ordered canonical page hashes and requested reading direction. An explicit `ltr` preserves the known legacy-v6 request path for the initial cache-only test; `auto` and `rtl` need their own qualified requests. Record source and analysis image hashes separately because analysis resizing may change request identity even when publication bytes match.
2. **Choose the smallest honest case.** Begin with original PDF `--pages 1`, using the existing full-PDF render cache verified against that original PDF. Build a raw one-image folder, CBZ and genuinely compressed CBR from that exact rendered JPEG. Retain the complete original PDF and cache; do not manufacture a one-page PDF/cache manifest or claim a re-encoded PDF has identical raster provenance. This first case validates actual whole-page conversion and single-page publication only.
3. **Extend to panel/escalation coverage.** Select a contiguous prefix containing a panelized page and a known automatic escalation, or use identical complete inventories in all containers and the same selected source indices. Repack the original rendered image bytes without ACBF/results as input. Every predecessor used as narrative context must be present in identical order for every format. A six-page prefix and original PDF `--pages 1,2,3,4,5,6` preserve the same preceding pages; qualify whether its exact current requests are cached before relying on it. Never trim context merely to force a cache hit.
4. **Make cache misses harmless.** Use a disposable copy of the durable ledger with completed response paths preserved and its normal cap unchanged. Override only `Budget.reserve` to reject every new reservation with an explicit offline-cache-miss error, and disable `Client.http` entirely. Actual completed-request lookup remains intact. Responses cache misses fail at preflight; Decisions misses fail reservation without adding a hold. Execute the real CLI/main, escalation controller and adapter. Do not replace `run_page`, validators or provider results with fixtures. Record any attempted uncached request as an explicit test failure, inspect why its identity changed, and stop without paid dispatch. Unknown/incomplete response entries remain blocked.
5. **Compare actual artifacts.** Each successful run must produce input manifest, actual routing/outcomes, proposed and final metadata, canonical page files, summary and CBZ. Compare ordered source/analysis image hashes; source-page mapping; classification and final ordered rectangles; selected tier and escalation/refinement/fallback reasons; all-page and legacy body counts; direction profile; and extracted ACBF semantics. Input-container hashes and source locators legitimately differ. New ACBF document UUIDs and the profile hash binding those exact XML bytes may differ; blanket archive-byte equality is not required. Original input bytes must remain unchanged.
6. **Read every generated book.** Serve each actual output CBZ from candidate staging and load it in the rendered phone reader. Verify overview before every page's panels, each ordered viewport, previous/next, whole-page nonduplication and single-page termination. Compare the served artifact hash with the generated file. Record all assertions, browser errors and screenshots. The RAR case must use the CBZ emitted by the real CBR conversion, not the equivalent-folder output.
7. **Close only the measured scope.** Record zero new calls and exact cache-hit counts for each run, untouched original/shared-ledger hashes, source versions and artifact hashes. A whole-page-only pass closes four-format whole-page integration; a panelized/escalating pass closes that bounded four-format segmentation path. Normalization, RTL, huge input limits and independently correct segmentation retain their separate gates. If the frozen candidate requires uncached quality requests, the blocked cache-only run is evidence of missing coverage, not a reason to weaken the policy or fabricate responses.

The full-book browser size limit and long-image analysis detail remain explicit operating limits to measure on real artifacts. They must not be confused with acceptance of every container or every comic layout.
