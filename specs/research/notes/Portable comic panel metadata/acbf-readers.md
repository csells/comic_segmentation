# ACBF metadata and readers

Research date: 2026-10-07. Evidence levels: **advertised** means first-party documentation; **code verified** means inspected upstream source at the linked commit; **executed** means the narrow scratch probe described below. No interactive reader was launched and no APK/desktop package was installed.

## What precisely does ACBF encode and how should it be packaged?

### Takeaway

ACBF 1.1 inside a normal CBZ is a real, open interchange mechanism for ordered panel polygons, with functioning OSS consumers. It supports the proposed output well, but does not establish universal reader support: package conservatively and qualify particular reader versions. — [Official format specification](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/wiki/Specifications); [desktop archive handling](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer/blob/a77484ab45cba6da29efa974b180cdf95a79b48e/src/fileprepare.py#L78-L106)

### Cited Findings

- **Released format:** official wiki calls 1.1 current and labels 1.2 additions as proposals. Use namespace `http://www.acbf.info/xml/acbf/1.1`; the authoritative repository carries 1.0 and 1.1 XSDs. Specification checkout inspected: `e033e004e2897fe20ad09cbd649a8ba1d6b38d09`, commit dated 2025-01-03. — [Specification](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/wiki/Specifications); [pinned 1.1 XSD](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/blob/e033e004e2897fe20ad09cbd649a8ba1d6b38d09/XML%20Schema/acbf-1.1.xsd)
- **Panels:** a page contains an image reference and zero or more `<frame points="x,y x,y ..."/>` elements. Coordinates are image pixels; ordered points describe a polygon. Frames may overlap. Reading order is the order of frame elements, not a separate numeric index or sorting algorithm. `bgcolor` is optional and inherits from page/body. If frames are absent, frame-level zoom is unavailable by the specification. — [Body specification, Frame](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/wiki/Body-Section-Definition#frame)
- **Integer interoperability:** desktop and Android readers explicitly parse each coordinate using Python `int`; Peruse uses integer `QPoint`s. Emit integer coordinates separated by exactly one ASCII space: both Python readers use `.split(' ')` without filtering empty fields; Peruse also splits on literal spaces. Do not copy the wiki examples' accidental double spaces or smart quotes. — [desktop frame parser](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer/blob/a77484ab45cba6da29efa974b180cdf95a79b48e/src/acbfdocument.py#L300-L316); [Android frame parser](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer-for-Android/blob/1be5e700e793dd864828bbc48927bf28d2f43970/acbf/acbfdocument.py#L286-L302); [Peruse frame parser](https://github.com/KDE/peruse/blob/476daab38422a91e2196920329541f3dc7967c30/src/acbf/AcbfFrame.cpp#L73-L95)
- **Container:** ACBF itself does not prescribe a ZIP container, but explicitly permits embedding `.acbf` plus externally referenced images in CBZ/CBR/CB7. For compatibility with ordinary archive readers, the specification says image names should sort alphabetically in reading order. The ACBF page sequence remains explicit in XML. Base64 image embedding and external URLs exist in the wider format but are unnecessary for the desired CBZ. — [Embedding section](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/wiki/Specifications#embedding-acbf-files-and-compatibility-with-popular-comic-book-formats)
- **Root placement is a real compatibility constraint:** desktop Viewer extracts the ZIP then checks only `os.listdir(tempdir)`, matching lowercase `acbf`; Android also checks only the extraction root (case-insensitively). Peruse recursively enumerates entries and selects the first `.acbf` in sorted order. Emit exactly one lowercase root file such as `metadata.acbf`; this basename is a convention supported by Peruse's writer, not a required ACBF standard name. — [desktop discovery](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer/blob/a77484ab45cba6da29efa974b180cdf95a79b48e/src/fileprepare.py#L100-L106); [Android discovery](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer-for-Android/blob/1be5e700e793dd864828bbc48927bf28d2f43970/acbf/fileprepare.py#L191-L198); [Peruse discovery](https://github.com/KDE/peruse/blob/476daab38422a91e2196920329541f3dc7967c30/src/qtquick/ArchiveBookModel.cpp#L243-L281); [Peruse metadata filename](https://github.com/KDE/peruse/blob/476daab38422a91e2196920329541f3dc7967c30/src/qtquick/ArchiveBookModel.cpp#L528-L539)
- **Image paths:** ACBF viewers resolve relative image paths against the metadata file's directory; Peruse constructs image-provider URLs using image href directly. Keeping metadata in archive root and using simple archive-relative paths avoids divergent nested-metadata resolution. Root images such as `0000.jpg`, `0001.jpg` are simplest; `pages/0000.jpg` is also an archive-relative reference when metadata is at root. — [desktop image loader](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer/blob/a77484ab45cba6da29efa974b180cdf95a79b48e/src/acbfdocument.py#L258-L279); [Peruse archive page construction](https://github.com/KDE/peruse/blob/476daab38422a91e2196920329541f3dc7967c30/src/qtquick/ArchiveBookModel.cpp#L272-L281)
- **Cover is structural:** `meta-data/book-info/coverpage` is mandatory and can itself contain frames; body pages follow it. Desktop and Android treat UI page 1 as the cover and map later page n to body index n−2. Peruse also prepends the cover to body pages. Listing the cover image again as the first body page therefore repeats it. This matters when source page one is a story page: it can be the ACBF cover *and retain its frames*, rather than being lost or duplicated. — [Cover definition](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/wiki/Meta-data-Section-Definition#coverpage); [desktop image/frame mapping](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer/blob/a77484ab45cba6da29efa974b180cdf95a79b48e/src/acbfdocument.py#L285-L316); [Peruse ordering](https://github.com/KDE/peruse/blob/476daab38422a91e2196920329541f3dc7967c30/src/qtquick/ArchiveBookModel.cpp#L275-L281)
- **Cover-only frames edge case:** desktop/Android `has_frames` discovery scans body pages only, even though `load_page_frames(1)` accepts cover frames. Android's auto-zoom option uses `has_frames`. A book whose only framed page is the cover therefore merits a reader test. This is a source-derived edge case, not an executed UI failure. — [desktop detection](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer/blob/a77484ab45cba6da29efa974b180cdf95a79b48e/src/acbfdocument.py#L253-L256); [Android detection](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer-for-Android/blob/1be5e700e793dd864828bbc48927bf28d2f43970/acbf/acbfdocument.py#L237-L240); [Android automatic zoom](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer-for-Android/blob/1be5e700e793dd864828bbc48927bf28d2f43970/main.py#L1178-L1182)
- **Reading direction is a draft trap:** `<reading-direction>LTR|RTL</reading-direction>` is labeled new in proposed 1.2 and is absent from 1.1 XSD. It affects navigation presentation; page/frame XML order still governs reading. Peruse source understands the field, but that does not make it a valid 1.1 element. Desktop/Android inspected parsers do not read it. The probe below confirms adding it causes 1.1 schema validation to fail. — [Reading direction specification](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/wiki/Meta-data-Section-Definition#reading-direction-new-in-12); [1.1 XSD](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/blob/e033e004e2897fe20ad09cbd649a8ba1d6b38d09/XML%20Schema/acbf-1.1.xsd); [Peruse parsing](https://github.com/KDE/peruse/blob/476daab38422a91e2196920329541f3dc7967c30/src/acbf/AcbfBookinfo.cpp#L235-L241)
- **XSD is necessary but insufficient:** `frameType.points` is merely `xs:string`. It does not check polygon validity, bounds, point count, coordinate syntax, or reading order. Independent geometry and archive-reference checks are required to substantiate compatibility. — [frameType](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/blob/e033e004e2897fe20ad09cbd649a8ba1d6b38d09/XML%20Schema/acbf-1.1.xsd#L512-L518)

### Inferences

- A defensible interoperability profile is ordinary ZIP/CBZ with unmodified numbered page images, one root `metadata.acbf`, cover represented once, integer pixel polygons in final reading order, and no dependence on draft extensions. This is a recommended compatibility subset inferred from the cited independent loaders; it is not an official profile.
- Any image rotation/resizing after segmentation requires transforming coordinates. A normalized Gemini box must be converted to the dimensions of the *exported* page image.
- Polygon metadata does not guarantee polygon-shaped cropping: Peruse and Android focus on rectangular bounds. Preserving polygons is still useful, but the presentation depends on the reader.

### Gaps

- No device/GUI testing of rotation, very tall panels, overlapping panels, cover-only books, spreads, RTL controls, nested images, JPEG EXIF orientation, or archive compression methods beyond the synthetic DEFLATE probe.
- No reviewed OSS ACBF consumer in this scope establishes direct CBZ guided reading on iOS or macOS. ACBF's existence alone cannot justify “any platform.”

## Which OSS readers really consume archive metadata and navigate frames?

### Takeaway

ACBF Viewer (Linux and historically Windows), ACBF Viewer for Android, and KDE Peruse (officially distributed for Linux) contain complete source paths from an embedded ACBF document to frame navigation. Android is the strongest identified mobile candidate; Linux has two independent implementations. Release availability and UI behavior still need qualification on target devices. — [desktop README](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer/blob/a77484ab45cba6da29efa974b180cdf95a79b48e/README.md); [Android release](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer-for-Android/releases/tag/v2.1); [Peruse app listing](https://apps.kde.org/peruse/)

It can inform a browser fallback discussion, not satisfy the “open my CBZ on any platform” requirement. — [Project README](https://github.com/ragtag/panel-by-panel)

### Inferences

- A reader matrix should have separate columns for normal CBZ opening, embedded panel-metadata ingestion, guided navigation, available binaries, and device testing. Conflating these produces misleading “supported” claims.
- The first product question should pin down must-have reading devices and whether a native installed reader is mandatory. A Linux+Android proof of interoperability is plausible from the reviewed sources; universal native coverage is unproven.

### Gaps

- No GUI execution, no measured usability/performance, and no verification that downloadable packages still run on today's OS versions.
- Peruse's CMake/Android source presence is not treated as proof of a downloadable functioning Android release. No macOS/iOS Peruse package was verified.
- No current Windows ACBF Viewer installer was established; historical README support is weaker than a tested contemporary binary.

## What was actually validated in a scratch environment?

### Takeaway

A synthetic two-image CBZ passed the authoritative ACBF 1.1 XSD and its extracted metadata was successfully parsed by the unmodified Android reader metadata class, returning the cover and ordered body frames. This verifies schema and parser interoperability only, not the Android archive/UI execution path. — [schema used](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF/blob/e033e004e2897fe20ad09cbd649a8ba1d6b38d09/XML%20Schema/acbf-1.1.xsd); [parser used](https://github.com/ACBF-Advanced-Comic-Book-Format/ACBF-Viewer-for-Android/blob/1be5e700e793dd864828bbc48927bf28d2f43970/acbf/acbfdocument.py)

### Cited Findings

- **Executed locally, 2026-10-07:** created only synthetic 200×300 PNGs and metadata under `/tmp/comic-acbf-research.OmIPZz/probe2/`. ZIP used DEFLATE and contained `0000.png`, `0001.png`, `metadata.acbf`. Archive SHA-256: `1dbc7753cb0ed31d93b02ccb7a3f519cab2f765ca534b2761c83f33c77dd77da`. Local artifacts: [results](/tmp/comic-acbf-research.OmIPZz/probe2/results.json), [probe source](/tmp/comic-acbf-research.OmIPZz/probe2.py), [CBZ](/tmp/comic-acbf-research.OmIPZz/probe2/probe.cbz), [XML](/tmp/comic-acbf-research.OmIPZz/probe2/metadata.acbf).
- **Method:** standard Python ZIP extraction, authoritative XSD validation using installed `lxml`, then the upstream `ACBFDocument` class. Only its unrelated constants module was stubbed (`default_font=''`, `PLATFORM='linux'`) to avoid configuration/font discovery; no reader methods were replaced. A first attempt lacked `PLATFORM` and failed, then a fresh `probe2` scratch directory was used. No GUI dependencies or global packages were installed, and no user files were touched. — [local probe](/tmp/comic-acbf-research.OmIPZz/probe2.py)
- **Observed results:** schema valid; reader valid; `has_frames=true`; one body page; cover resolves to `0000.png`; next page resolves to `0001.png`; cover returns one polygon; body returns two polygons in XML order. First body polygon: `(110,10) (190,10) (190,140) (110,140)`; second: `(10,160) (190,160) (190,290) (10,290)`. — [recorded results](/tmp/comic-acbf-research.OmIPZz/probe2/results.json)
- **Negative controls:** replacing a frame's points with `not-points` still passed XSD validation; adding draft `<reading-direction>RTL</reading-direction>` failed 1.1 schema validation. These illustrate why valid XML/XSD alone does not establish safe geometry or interoperability. — [recorded results](/tmp/comic-acbf-research.OmIPZz/probe2/results.json)
- **Shipped Peruse source check:** fetched `v1.80` files and confirmed `ArchiveBookModel.cpp` has ACBF suffix selection, while `ImageBrowser.qml` has both `nextFrame()` and `focusOnFrame()`. The tag is `bc0eaa550171f093bea0b25d02eb9066a99af0ca`. This was source inspection, not executed Qt UI. — [v1.80 archive model](https://github.com/KDE/peruse/blob/v1.80/src/qtquick/ArchiveBookModel.cpp); [v1.80 image browser](https://github.com/KDE/peruse/blob/v1.80/src/app/qml/viewers/ImageBrowser.qml); [local results](/tmp/comic-acbf-research.OmIPZz/probe2/results.json)

### Inferences

- The mechanism is concrete enough to justify preserving ACBF as a leading candidate in the vision. A later reader acceptance check should use the user's real comic plus difficult fixtures, on actual selected reader versions.

### Gaps

- The probe did not run the Android `FilePrepare` class, touch/swipe handling, image rendering, ZIP discovery inside the installed app, or Peruse/desktop Viewer execution. Those stages are source verified only.
- Scratch links are machine-local and may disappear when `/tmp` is cleared; the outputs and exact upstream commits are recorded here for durable interpretation.
