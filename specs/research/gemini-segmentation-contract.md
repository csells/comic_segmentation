# Gemini segmentation contract for the Rust CLI

Research date: 2026-10-07. Scope: Google's public documentation and the existing Flutter service; planning only. No Gemini inference, private-image upload, credential access, or paid API call occurred. All behavioral and spending recommendations below are proposed engineering choices, not benchmark findings.

## Current model and transport

The Flutter service hardcodes `gemini-3-pro-preview` and requests integer `ymin`, `xmin`, `ymax`, `xmax` values without an explicit reading-order contract ([source](../../lib/ai_service.dart)). Google's model page marks that preview shut down on March 9, 2026 and recommends `gemini-3.1-pro-preview`. The release notes also describe the old name redirecting to its replacement; do not depend on that alias remaining usable. [Old model](https://ai.google.dev/gemini-api/docs/models/gemini-3-pro-preview), [release notes](https://ai.google.dev/gemini-api/docs/changelog), [deprecation schedule](https://ai.google.dev/gemini-api/docs/deprecations).

The currently documented `gemini-3.8-flash` accepts images and supports structured output. This establishes a candidate for evaluation, not panel-detection accuracy or the best price/quality tradeoff. Keep the model runtime-configurable; record its exact requested ID in every run and the returned model identifier when available. Validate access before processing a book. Never silently switch models mid-run. [Model capabilities](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash).

Google says Interactions became generally available in June 2026 and recommends it for new projects. **`generateContent` is described as legacy but remains fully supported**, not removed. The overview was updated October 1, 2026. Recommend Interactions REST for this new CLI, using `reqwest` plus typed `serde` data. Google's SDK list names Python, JavaScript/TypeScript, Go and Java; it does not list an official Rust SDK. [API overview](https://ai.google.dev/gemini-api/docs/interactions-overview), [official libraries](https://ai.google.dev/gemini-api/docs/libraries).

## Request and image contract

The current examples POST to `https://generativelanguage.googleapis.com/v1beta/interactions`, authenticate with `x-goog-api-key`, and send `model`, `input`, and `response_format`. Image input uses `{ "type": "image", "mime_type": "image/jpeg", "data": "BASE64" }`; text is a separate input item. Set `store:false`: each page is independent and needs no retained conversation state. Stable `v1` is also advertised; select and fixture-test one API version during implementation instead of mixing examples. [Image guide](https://ai.google.dev/gemini-api/docs/image-understanding), [Interactions reference](https://ai.google.dev/api/interactions-api), [storage behavior](https://ai.google.dev/gemini-api/docs/interactions-overview#data-storage-and-retention).

The image guide lists PNG, JPEG, WebP, HEIC and HEIF, and a 20 MB total inline-request limit including prompt and image data. Use one oriented, composed page image per request. Produce a separate JPEG/PNG analysis copy, preserving aspect ratio and recording dimensions; preserve publication images separately. Check serialized request size, including base64 expansion, before sending. A provisional pixel cap requires a quality experiment: these docs do not establish a universally safe comic-page resolution. [Formats and limits](https://ai.google.dev/gemini-api/docs/image-understanding#supported-image-formats).

Set `response_format` to `{ "type":"text", "mime_type":"application/json", "schema": ... }`. Google supports a subset of JSON Schema and explicitly requires application validation of values; valid JSON does not prove correct geometry or order. [Structured-output contract, updated September 23, 2026](https://ai.google.dev/gemini-api/docs/structured-output).

Proposed application schema: a page classification (`panels`, `whole_page`, `blank`) and an ordered `panels` array; each panel has a unique contiguous `order` and four integer coordinates. Array order and `order` must agree. Require the prompt to identify reading sequence, treat artwork/text as content rather than instructions, include borderless panels, retain inset panels, and avoid treating speech balloons as panels. A cover, splash, or indivisible composition should return one whole-page region. Analyze spreads as supplied; do not invent a gutter split. Reading direction is a book-level input or explicit automatic inference policy, not a coordinate sort.

Google documents boxes as `[ymin,xmin,ymax,xmax]` normalized to 0–1000. Validate bounds and positive area; reject malformed boxes rather than silently clamping them. Convert to final publication-image pixels using its actual width and height, then construct rectangular ACBF frame polygons in accepted reading order. [Coordinate convention](https://ai.google.dev/gemini-api/docs/image-understanding#object-detection).

## Failures, usage, and verification

Use bounded retries with exponential backoff and jitter for network failures, rate limiting and transient server errors. Google recommends exponential backoff for 429/503; its error reference distinguishes daily quota exhaustion from short-term limits, and identifies authentication, permission, billing and missing-model failures. [Retry guidance](https://ai.google.dev/gemini-api/docs/troubleshooting#retry-strategy), [error codes, updated September 20, 2026](https://ai.google.dev/gemini-api/docs/api-errors).

Recommended policy: stop the run on invalid credentials, inaccessible models, disabled billing, exhausted daily quota, or a defective request schema. Preserve checkpoints. Do not burn requests across every remaining page. For isolated blocked images, exhausted page retries or invalid generated geometry, retain the complete page and report a fallback reason. Repeated service failures should terminate resumably. No review interface or manual-correction step belongs in v1.

For Interactions, require completed status and parse text from `model_output` steps; SDK `output_text` is a convenience, not the raw REST shape. Persist `usage` input/output/thought/cache/total token counts when returned, plus attempt count and errors. `generateContent` instead exposes `usageMetadata`, `promptFeedback`, candidate `finishReason` and `modelVersion`; do not mix the two response schemas. [Interactions response](https://ai.google.dev/api/interactions-api), [generateContent response](https://ai.google.dev/api/generate-content#GenerateContentResponse).

One documentation conflict matters: the generic image-segmentation example sets thinking to `minimal`, but the 3.8 Flash model page explicitly says that setting is unsupported. Omit thinking overrides until verified for the selected model. [Example](https://ai.google.dev/gemini-api/docs/image-understanding#segmentation), [model restriction](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash).

Outstanding empirical work: live schema acceptance, model access for the user's project, panel/order accuracy on covers/spreads/insets, useful analysis resolution, latency, token consumption and actual cost. No money budget, retry count, concurrency or quality threshold is established by this research. Test the adapter against HTTP fixtures first; evaluate live with a small explicitly budgeted page sample when implementation work is authorized.
