## Candidate contract

`auto_convert.py` adds `Client(..., retry_transient=())` and `--retry-transient SHA256`. There is no automatic retry. Eligibility requires a recorded error whose exact prefix is `HTTP 503:`, followed by valid JSON with an `error` object containing `type: server_error`, a nonempty message, and explicit null `param` and `code`. No provider message or comic-specific content is matched. Unstructured errors, other statuses, other error types, and missing/nullability-mismatched fields remain blocked.

The saved original request must bind the original request ID/fingerprint, endpoint and request kind, with no `retry_of`. The recovery ID is SHA256 of `explicit-transient-server-recovery-1:` followed by the original fingerprint. The provider body and ordinary cache fingerprint are unchanged. The old reservation is never removed or settled by this operation. A separate durable reservation precedes dispatch and remains held if the recovery also fails.

Original successful responses are reused before recovery eligibility is considered. The client also checks all existing timeout, quota and transient recovery identities before starting a recovery: a saved success is reused; an unsettled recovery without a response blocks further replay. Naming the recovery ID, changing recovery type, opening a new client, or repeating the command does not grant another recovery.

Quality policy remains `automatic-source-ownership-v30`. New runs separately record `transport_policy: explicit-structured-503-recovery-v1`; frozen V30 runs remain unchanged and cannot be resumed into the changed run configuration.
